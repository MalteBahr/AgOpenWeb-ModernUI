Selected concept · design exploration

A · Persistent line rail (right)

Preferred direction · user feedback

Default here means “shown first in this mockup”, not the application default. Concept A’s right-hand rail reflects user feedback about right-handed reach in a tractor-mounted tablet, not a measured reach study; Classic remains the application’s default until the README gates and a separate maintainer agreement are met. The left Settings trigger and its simulated menu are proposals: no setting is live, and the trigger stands in for the Classic Menu rather than replacing its real settings, diagnostics or recovery paths. A left-handed rail mirror is an open decision, not built here.

Why this is honest about state: A>B and length values on cards are illustrative; the current scene contract sends no heading or length. AB/curve recording is client-local today, so a banner cannot claim it survived a reload or control loss. The “fields locked while recording” guard is a proposal, not current behavior. One-tap A+, line-card selection and finishing a recording are all open steering-safety decisions; this page does not claim an approved command or confirm sequence. Line selection would have to be host-confirmed and steering-safe, and every action shown is operator-only; observer and control-loss states are not simulated here. The sample map and its field data stay the same when you switch fields. Nothing on this page is implemented functionality or a commitment.

Companion to Docs/UI_DESIGN_EXPLORATION.md. Four concepts compared at the project's 1280×800 CSS-px landscape reference size; the page opens on Concept A with its rail on the right. The default Fit view scales the whole reference screen to the window; use View: 1:1 in the toolbar to inspect the true CSS-px sizes and scroll the stage. This page is an independent static visual mockup: single file, inline CSS/JS/SVG, no network requests, no build step and no connection to AgOpenWeb. Icons and the map are drawn for illustration.
